# Режим преподавателя (человек) + B2B для школ

Сейчас в приложении **«Учитель»** = AI-компаньон Tearz (уроки/чат/тренировки).  
Этот документ — про **другого** продукт: живой преподаватель и образовательная организация.

Рабочие имена в коде (чтобы не путать с AI):

| UI (RU) | Код |
|---------|-----|
| Режим преподавателя | `instructor` |
| Класс | `class` / `cohort` |
| Материал | `material` |
| Организация / школа | `org` |
| Ученик в классе | `learner` (роль в классе, не путать с глобальным user) |

AI-учитель остаётся как есть (`teacher-*`).

---

## Зачем

1. Препод собирает/шарит материалы ученикам внутри Tearz.  
2. Ученики открывают материал и проходят практику в уже знакомом UX (чат / drills / хаб).  
3. Позже: школа платит за организацию (кабинеты, классы, аналитика) — **услуга B2B**, не IAP в сторе для учеников на старте.

---

## MVP (фаза 1) — без оплаты

Цель: один препод → один класс → ссылка/код → ученики видят материалы.

### Роли

- **instructor** — создаёт классы и материалы, шарит код/ссылку.  
- **learner (в классе)** — видит выданные материалы, проходит их.  
- Один аккаунт может быть и тем и другим в разных классах.

### Сущности

```
Org? (фаза 2)
  └── Class
        ├── InviteCode / deep link
        ├── Members (userId, role)
        └── Materials[]
              ├── title, body / lessonRef / attach
              ├── assignedAt
              └── progress per learner (фаза 1.5)
```

**Материал MVP** — одно из:

1. Ссылка на существующий AI-урок / сохранённый teacher-lesson id (если уже есть у препода).  
2. Текстовый раздаточный (markdown/plain) + опционально файл.  
3. «Пакет тренировки» — набор заданий (позже связать с `teacher-exercise-set`).

### UX

**Профиль / хаб → «Режим преподавателя»**

- Создать класс (название, язык).  
- Код приглашения: `TEARZ-XXXX` + share sheet.  
- Список материалов → «Выдать классу».  
- Простая лента: кто зашёл по коду (опционально в MVP — только счётчик).

**Ученик**

- «Вступить в класс» → ввод кода.  
- Вкладка / секция «Мои классы» → материалы от препода.  
- Открыл материал → чтение + «Практиковать» (ведет в drill/чат, если привязано).

### Техника MVP

| Слой | Решение |
|------|---------|
| Клиент | `contexts/instructor-context.tsx`, типы в `types/instructor.ts` |
| Хранение v0 | AsyncStorage на устройстве препода + deeplink join по коду **через API** (иначе ученик не увидит) |
| API | `POST /api/instructor/classes`, `materials`, `join`, `list` на существующем companion-сервере |
| Auth | нужен стабильный `userId` (сейчас auth/OTP — довести до рабочего входа до B2B) |

> Без серверной синхронизации «поделиться» между двумя телефонами нельзя. Локальный прототип UI — ок для демо; шаринг = API.

### Не в MVP

- Оплата, счета, юр. лица  
- SSO школы  
- Полная аналитика успеваемости  
- Редактор курсов уровня Moodle  
- Замена AI-учителя

---

## Фаза 2 — организация (B2B)

- **Org**: школа / курсы / репетиторский центр.  
- Админ org приглашает преподавателей.  
- Несколько классов, брендинг (опционально).  
- Биллинг: **внесторовая** подписка org (счёт / договор / RuStore/Play B2B где уместно) — не смешивать с монетами ученика.  
- Отчёты: активность класса, прохождение материалов.

Монетизация: «Tearz для школ» — seat-based или class-based monthly.

---

## Фаза 3 — продукт глубже

- Назначение домашки с дедлайном  
- Проверка открытых ответов преподом  
- Импорт своих PDF/карточек  
- White-label / LMS embed

---

## Связь с текущим AI Teacher

| AI Teacher | Instructor mode |
|------------|-----------------|
| Tearz объясняет и даёт drills | Человек курирует группу |
| Уроки в `teacher-journey` | Материалы класса на сервере |
| Личный прогресс | Прогресс в контексте класса |

Мост: материал может **открывать** AI-урок или drill-пакет — не дублировать весь движок.

---

## Критерии готовности MVP

- [ ] Роль instructor включается в профиле  
- [ ] Создание класса + код  
- [ ] Ученик входит по коду на другом аккаунте  
- [ ] Препод публикует ≥1 материал, ученик его видит  
- [ ] Материал открывается в приложении  
- [ ] Документ для пилота школы (1 страница value prop)

---

## Порядок работ (инженерный)

1. Типы + API-контракт + пустой UI-каркас (этот репозиторий).  
2. Серверные эндпоинты + хранение (Postgres/SQLite на API).  
3. Share / join flow.  
4. Привязка материала → drill/lesson.  
5. Пилот с 1–2 преподами.  
6. Org + биллинг.
